open-ui mounts as **one layer** over the game you already have. You don't build the
HUD — you mount it, configure it, and then **talk to it**.

There are two bindings over the same headless core. Everything below uses
`@open-slot-ui/dom`, which renders the HUD as real markup and wears the stylesheet
you pass — it is what the [gallery](/gallery/) shows. `@open-slot-ui/pixi` takes the
same spec and the same calls, and draws onto a PixiJS stage instead.

## Requirements

- Node 20+ and a package manager (pnpm recommended)
- A page to mount into. The DOM binding needs nothing else; the canvas binding needs
  a PixiJS v8 `Application`, whose `stage`, `ticker` and `renderer` it shares.

## Install

```bash
pnpm add @open-slot-ui/core @open-slot-ui/dom
```

## Mount the whole HUD in one call

```ts
import { mountDomHud } from '@open-slot-ui/dom';

const hud = mountDomHud({
  currency: { code: 'USD', symbol: '$', display: 'symbol', position: 'prefix', decimals: 2 },
  betLadder: { levels: [0.1, 0.2, 0.5, 1, 2, 5, 10], index: 3 },
}, {
  // The library ships NO stylesheet: this is the skin your game wears.
  skin: { href: '/ui.css', font: { family: 'icomoon', src: '/icons.woff2' } },
});
```

That puts a correct, laid-out HUD on screen — balance, stake and its ladder, win,
the round button, autoplay, turbo, the ☰ menu, the info window — all wired, all
responsive, on desktop and on a phone. To shape it, pass more
[config](/guides/configuration/):

```ts
const hud = mountDomHud({
  turbo:    { modes: 3 },
  autoplay: { mode: 'options', lossLimits: [5, 20, 50] },
  spin:     { press: 'hold-to-spin' },
  hud:      { features: { buyFeature: true, history: true, info: true } },
}, { skin });
```

## The look is yours

The DOM binding renders the ids and classes a casino skin already expects, so a
stylesheet written for that markup dresses it as-is. Nothing in the library paints
a colour of its own — see [how it fits together](/docs/anatomy/).

## Talk to it: events out, commands in

The boundary is the whole product. The game **listens** for intents and
**commands** the display — it never reaches into a widget. `hud.ui` is the headless
façade; `hud.on(...)` subscribes; `hud.setBalance(...)` is a shortcut.

```ts
hud.on('spinRequested', async () => {
  hud.ui.spin.busy();                          // command in: show the spinning state
  hud.setBalance(hud.ui.balance.get() - hud.ui.bet.get());
  const result = await game.spin();            // your RGS call
  if (result.win) hud.setBalance(hud.ui.balance.get() + result.win);
  hud.ui.spin.idle();
});
```

## Add it to any slot

That's the whole integration: mount it, wire `spinRequested` to your spin, and feed
results back with `hud.setBalance()`. The HUD owns its own layout, states and
teardown; your game owns the round. Every state it can be in is a
[story you can open](/gallery/).

## Tear it down cleanly

```ts
hud.dispose();   // removes the layer + every listener, tween and timer
```

<blockquote>
  Nothing leaks: every subscription returns a disposer and the base type enforces
  teardown (Charter&nbsp;P12).
</blockquote>
